# MAVIS 框架配置指南

本文档面向第一次接触框架、需要配置场景和角色的使用者。目标:让你知道"想改什么 → 去哪个文件 → 改哪个字段"。

## 一、配置总览

框架的配置分散在四个地方,各管一件事:

| 配置位置 | 管什么 | 什么时候改 |
|---|---|---|
| `data/config.json` | 所有角色的**全局默认行为**(LLM、感知、日程、对话) | 换模型 / 调模拟细节 |
| `frontend/static/assets/village/agents/<角色>/agent.json` | **单个角色的**人设(名字、性格、位置) | 加角色 / 改人设 |
| `frontend/static/assets/village/maze.json` | 地图(格子、房间、碰撞) | 换场景布局 |
| `scenarios/investment/story.json` | 剧情事件(危机注入) | 加市场波动/投诉等事件 |
| `scenarios/investment/relationships.json` | 角色关系(谁和谁什么关系) | 定义角色协作 |

> 注意:前三个文件是"全局默认"与"单个角色"的**合并关系**——`data/config.json` 提供默认值,`agent.json` 可以覆盖同名字段。

## 二、按目标查配置

### 2.1 我想换一个大模型(如改 DeepSeek)

改 `data/config.json` 的 `agent.think.llm`:

```json
"llm": {
  "provider": "openai",                // ollama=本地 / openai=DeepSeek等兼容API
  "model": "deepseek-chat",            // 模型名
  "base_url": "https://api.deepseek.com/v1",  // API 地址
  "api_key": "",                       // 密钥建议用环境变量 LLM_API_KEY,不要写这里
  "concurrency": 4                     // 并发上限,一般不用改
}
```

### 2.2 我想加一个新角色

1. 复制 `frontend/static/assets/village/agents/` 下任意一个角色目录,改成新名字
2. 编辑新目录的 `agent.json`:

```json
{
  "name": "新角色名",          // 必须与其他角色不重名
  "coord": [12, 8],           // 初始位置(格子坐标,看地图)
  "currently": "新角色当前在做什么",  // 开场状态描述
  "scratch": {
    "age": 35,                // 年龄
    "innate": "性格底色,如:谨慎、重视数据",     // 先天性格
    "learned": "后天习惯,如:每天复盘交易",       // 后天习得
    "lifestyle": "生活方式,如:早睡早起",         // 生活习惯
    "daily_plan": "日常安排概述"                 // 日常计划
  },
  "spatial": {
    "address": {"living_area": ["the Ville", "投资咨询中心", "休息区"]},  // 睡觉地址
    "tree": { "the Ville": { "投资咨询中心": { "休息区": ["床"] } } }     // 空间树
  }
}
```

3. 角色会自己通过 LLM 生成日程、感知、对话、反思——你只需要提供人设,不需要写行为逻辑。

### 2.3 我想改某个角色的性格/语气

只改该角色 `agent.json` 的 `scratch` 四项即可。`innate`(先天)最影响决策风格,比如老周写"情绪化、易被行情带动",林晚晴写"风险敏感、强调数据"。

### 2.4 我想加一个剧情事件(危机注入)

改 `scenarios/investment/story.json`,在 `events` 数组里加一条:

```json
{
  "id": "s-003",
  "time": "10:30",                  // 触发时间(HH:MM,模拟时钟走到这时触发)
  "event_type": "监管约谈",          // 事件类型,会出现在记忆里
  "content": "监管机构约谈投资咨询中心,要求说明近期组合操作依据",  // 事件描述
  "targets": ["沈砚之", "苏清越"],   // 影响谁:"all"=所有角色,或列出角色名
  "expected": "各角色评估影响并调整策略",   // 期望触发行为(描述性,供人理解)
  "importance": 9                   // 重要性1-10,数字越大越影响角色后续思考
}
```

规则:
- `time` 必须是模拟时钟会经过的时间(从 `--start` 到结束之间)
- `targets` 用 `"all"` 影响所有人,或写角色名数组只影响指定角色
- `importance` 决定事件在记忆里的权重:10=监管级,5=一般舆情,不填默认10
- 事件会写入目标角色的记忆,影响他们之后的感知、对话、反思——你不需要写任何代码

### 2.5 我想定义角色之间的关系

改 `scenarios/investment/relationships.json`,在 `relations` 数组里加一条:

```json
{
  "agents": ["老周", "沈砚之"],      // 关系涉及的两位角色
  "type": "客户-顾问",              // 关系类型(业务语义)
  "direction": "老周→沈砚之",       // 方向
  "trigger": "每天下午3点，老周到会议室找沈砚之咨询行情与配置建议",  // 互动约定
  "frequency": "high"               // high/medium/low:互动频率
}
```

这条关系会被注入到两位角色对话时的上下文——老周和沈砚之对话时,LLM 会知道"老周是客户,下午3点来咨询"。

### 2.6 我想调整模拟细节(步长/时长/反思阈值)

改 `data/config.json`:

- `agent.percept`:感知范围(`vision_r`=视野半径,`att_bandwidth`=注意力上限)
- `agent.schedule`:日程生成(`diversity`=每日活动多样性要求,`max_try`=生成尝试次数)
- `agent.think.poignancy_max`:反思触发阈值(重要性累计超过它就反思,默认150)
- `agent.chat_iter`:一场对话最多几轮
- 启动参数(步长/时长)在启动命令里:`--stride 2`(每步2分钟)、`--start`(起始时间)、`--step 0`(持续运行)

### 2.7 我想换地图

`maze.json` 的格式较复杂(360 个格子、地址、碰撞),不建议手改。两种方式:
- 参考 `docs/修改地图` 章节(根 README)用 Tiled 导出后转换
- 在现有地图上微调(改几个格子的地址/碰撞)比从零建快

## 三、配置与代码的关系(为什么这样设计)

框架把配置分成"人设(agent.json)+ 场景(story/relationships)+ 默认行为(config.json)"三部分,是为了**换业务不用改代码**:

- 想换一个全新业务(如医疗):新建 `scenarios/<新业务>/`,填角色人设和剧情,框架逻辑零改动
- 想调模拟手感:改 `data/config.json` 的默认值
- 想让角色有"性格":改 `agent.json` 的 `scratch`

框架本身只读配置、不写配置(存档除外),所以配置可以放心改,改坏了大不了删存档重跑。

## 四、配置生效时机

- **修改后需重启模拟**才生效(框架在启动时读一次配置)
- 已运行的模拟存档不受影响,重启后用 `--resume` 会基于旧状态继续(新增的剧情事件从重启后的时间开始检查)
- 想从头验证配置效果:用新模拟名启动,或删掉对应存档目录

## 五、常见问题

**改了人设但角色行为没变**:确认重启了;性格影响是渐进的(通过记忆和对话),不是立即的。

**加了剧情事件但没触发**:检查 `time` 是否在模拟时间范围内;确认 `targets` 写法(`"all"` 或角色名数组);重启后从事件时间之前开始跑。

**新角色地图上不显示**:确认 `agent.json` 的 `coord` 在地图范围内,且角色目录在 `frontend/static/assets/village/agents/` 下。

**改了配置模拟崩了**:多半是 JSON 格式错误(缺逗号/引号)。用任意 JSON 校验工具检查一下。
