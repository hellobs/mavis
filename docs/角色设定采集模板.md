# 智能体角色设定采集模板

> 用途：请业务方按此模板提供角色设定，我们将其直接映射为系统配置。
> 结构分两部分：**① 角色基本信息表（每个角色一行）② 角色关系表（每对关系一行，独立配置）**。
> 角色是"点"，关系是"边"：关系单独成表，避免双方重复填写导致不一致。

---

## 一、角色基本信息表（每个角色一行）

| 角色名 | 职位/角色 | 年龄 | 性格特质(3-4词) | 背景设定(2-3句) | 作息习惯 | 典型一天(按时间段) | 当前状态 | 所属区域/工位 |
|---|---|---|---|---|---|---|---|---|
| 沈砚之 | 首席投资顾问 | 42 | 沉稳、理性、有远见 | 从业二十年价值投资派，擅长宏观研判与资产配置 | 早6晚10:30，咖啡看盘 | 上午会议室研读行业报告；下午写配置方案；下午3点接待老周咨询 | 整理客户资产配置方案 | 会议室 |
| 老周 | 资深散户 | 56 | 热情、健谈、情绪化 | 炒股二十年，消息灵通缺方法，易追涨杀跌 | 早公园听消息，晚看财经节目 | 上午走廊看盘听消息；下午3点找沈砚之咨询 | 盯着行情犹豫加仓 | 走廊/咨询台 |
| ... | | | | | | | | |

> ⚠️ "典型一天"最关键：**决定角色何时出现在哪里 → 空间共现 → 是否与其他角色碰面**。

---

## 二、角色关系表（每对关系一行，独立配置）

> 5 个角色最多 10 对关系，但**只需填业务上"有特殊关系"的对子**；没填的默认无特殊约束，靠空间共现自然交互。
> 关系只在此表定义一次，系统会自动注入到相关角色的"典型一天"中（保证双方一致，不重复）。

| 关系对(A - B) | 业务关系类型 | 谁主动(direction) | 互动约定(trigger：何时/何地/做什么) | 频率 |
|---|---|---|---|---|
| 老周 - 沈砚之 | 客户-顾问 | 老周→沈砚之 | 每天下午3点，老周到会议室找沈砚之咨询行情与配置建议 | 高 |
| 陈慕白 - 苏清越 | 数据协作 | 双向 | 上午在资料室交叉验证新能源财报关键指标 | 中 |
| 林晚晴 - 沈砚之 | 风控-决策 | 林晚晴→沈砚之 | 评审会前，林晚晴到会议室提交风险评级结果 | 中 |
| ... | | | | |

**字段说明：**
- **关系对**：哪两个角色（顺序无关）
- **业务关系类型**：客户-顾问 / 数据协作 / 风控-决策 / 同事 / 审批 等
- **谁主动**：单向（A→B）或双向（A↔B）——决定"互动约定"写入谁的典型一天
- **互动约定**：何时、何地、做什么——**这是交互能否发生的核心**
- **频率**：高 / 中 / 低——高频率的可加强约束（必发生）

---

## 三、填写说明（如何生效）

| 你填的 | 映射到系统的什么 | 效果 |
|---|---|---|
| 角色基本信息表 | `agent.json`（名字/性格/背景/作息/当前状态） | 决定角色"是谁、怎么思考" |
| 典型一天 | `daily_plan`（注入日程生成提示词） | 决定"他在哪" → 空间共现 → 碰面基础 |
| 关系表·互动约定 | 自动写入主动方的 `daily_plan`（如"下午3点去会议室找沈砚之"） | **引导/保证该对角色产生交互** |
| 关系表·频率=高 | 可选 `relationships.json` 强约束（关系强的更易发起对话、不受冷却限制） | 让指定协作必然发生 |

---

## 四、关系配置逻辑（为什么这样设计）

1. **角色（点）与关系（边）分离**：5 个角色配置各自独立；关系只在一张表里定义一次，系统映射时自动注入双方日程，**不会两边写重复导致矛盾**
2. **稀疏配置**：10 对潜在关系只需填业务上重要的几对（通常 3~5 对），其余自然涌现
3. **方向性**：单向关系只写主动方的日程（如"老周下午去找沈砚之"）；双向关系写双方
4. **频率分级**：高 = 强约束（必发生，加 relationships.json）；中 = 引导；低 = 不配置靠自然碰面
