# MAVIS 框架接入指南

本文档面向所有需要接入 MAVIS 框架的开发者与协作方,说明框架的整体用法、接入方式与消息契约。阅读对象包括:前端可视化开发者、Unity 客户端开发者、业务场景配置方、决策/治理平台对接方。

## 一、框架定位与整体架构

MAVIS 是一个自研的生成式智能体仿真框架,以斯坦福 Generative Agents 论文的算法为基础(记忆流、三因子检索、反思、递归日程分解),在其上增加了三件论文之外的事:与传输无关的消息契约、结构化的决策留痕导出、可插拔的存储与组件架构。

框架遵循"协议接入、代码隔离"的原则:外部系统不 import 框架内部代码,只通过两类出口对接——实时消息(WebSocket)与离线文件(存档、决策导出)。框架核心不依赖任何前端技术(Phaser、Unity)或通信技术(WebSocket、SSE),这些都被视为可替换的传输与渲染层。

代码组织如下。`framework/core` 为纯逻辑层,包含 Agent 生命周期(思考、感知、日程、反应、对话、反思)、事件模型、日程、空间记忆、联想记忆与三因子检索、记忆存储抽象、提示词系统。`framework/scene` 为空间层,包含地图、碰撞、寻路与地址索引。`framework/runtime` 为运行时层,包含消息协议、LLM 适配与 Provider、游戏容器、并行调度器、实时压缩器、统一日志。`framework/output` 为输出层,包含决策事件导出。`framework/config` 为配置层,包含场景配置加载与模拟配置(新开、续跑)。

`live_fastapi.py` 是唯一的运行入口,它组合了框架的 Game、Simulator、LiveCompressor,对外提供页面渲染与 WebSocket 服务。`data/config.json` 是全局默认配置(LLM、感知、日程、对话等默认参数)。`scenarios/` 是业务场景目录,一个业务对应一个子目录。`frontend/` 是 Phaser 前端壳,`results/` 存放模拟存档、压缩回放与决策导出产物。

## 二、快速开始

### 2.1 环境要求

需要 Python 3.12,一个可用的 LLM 后端(Ollama 本地或 OpenAI 兼容 API),以及前端静态资源。推荐在隔离的虚拟环境(如 uv)中运行,已安装 fastapi、uvicorn、websockets。

### 2.2 启动实时模拟

在 `generative_agents/` 目录下执行:

```bash
.\.venv-live\Scripts\python.exe live_fastapi.py --name sim-test --start "20250213-09:30" --stride 2 --step 0 --port 5001
```

参数含义:`--name` 为模拟名称(存档按此分目录);`--start` 为起始时间;`--stride` 为每步推进的游戏分钟数(2 表示较细腻的推演);`--step` 为步数,0 表示持续运行直到手动停止;`--resume` 从既有存档续跑;`--port` 为服务端口。

启动后浏览器访问 `http://127.0.0.1:5001/` 可边跑边看,WebSocket 端点位于 `ws://127.0.0.1:5001/ws`。

### 2.3 从断点续跑

```bash
.\.venv-live\Scripts\python.exe live_fastapi.py --name sim-test --resume --stride 2 --step 0 --port 5001
```

续跑时框架读取 `results/checkpoints/sim-test/` 下最新的存档,恢复 Agent 的记忆、日程、位置与对话,并从存档时间之后继续推进。

## 三、四类接入者用法

框架对外的接入面按消费方分为四类。每类接入者只接触自己需要的那一层,不需要理解框架内部实现。

### 3.1 前端可视化开发者(实时消息消费者)

这类接入者的职责是把模拟过程可视化,包括地图、角色移动、对话、时间。接入方式为连接 WebSocket 端点并解析 JSON 消息。

连接 `ws://127.0.0.1:5001/ws` 后,服务端会先推送一条 `init` 确认消息;若模拟已在运行,接着推送一条 `snapshot` 全量快照(包含当前所有 Agent 的位置与动作),供新连接者初始化画面。此后,模拟每推进一格,会收到若干条 `agent` 消息(每个 Agent 思考完成推一条)、整步完成时收到 `time` 消息、对话逐句生成时收到 `chat_line` 消息、模拟结束或异常时收到 `done` 或 `error` 消息。

所有消息的字段定义见本文档第四节。前端只依赖这些消息结构,不依赖框架代码。Phaser 前端已按此契约实现;Unity 客户端可参照第四节编写等价的 WebSocket 客户端,仅替换渲染层。

### 3.2 Unity 客户端开发者

Unity 端与前端可视化属于同一类接入者,使用同一份消息契约。区别仅在渲染:Unity 负责把 `coord`(格子坐标)换算为世界坐标、按 `path` 逐点平滑移动角色、按 `chat_line` 显示对话气泡、按 `time` 更新时钟。

框架侧为零改动。若未来需要更紧凑的传输(如 MessagePack 或二进制帧),只需在传输层替换,消息结构不变——这是协议与传输解耦的保证。

### 3.3 业务场景配置方(换场景、换业务)

换业务不需要写代码,只需要在 `scenarios/` 下新建一个目录,按约定放置配置文件:

```
scenarios/<业务名>/
├── agents/<角色名>/agent.json   # 角色人设(姓名、坐标、当前状态、性格、生活习惯)
├── scene/maze.json              # 逻辑地图(格子、地址、碰撞)
├── relationships.json           # 角色关系(可选,边列表)
└── story.json                   # 剧情事件(可选,危机注入)
```

`agent.json` 必须包含 `name`、`coord`、`currently`、`scratch`(人设)、`spatial`(空间记忆)等字段,格式与现有 `frontend/static/assets/village/agents/` 下的示例一致。`maze.json` 的格式与 `frontend/static/assets/village/maze.json` 一致,可由 Tiled 导出的数据经转换工具生成,或直接参考现有地图改写。

`relationships.json` 与 `story.json` 是可选增强。`relationships.json` 的根结构为 `{"relations": [...]}`,每条关系声明两个角色、关系类型、方向、互动约定与频率。`story.json` 的根结构为 `{"events": [...]}`,每条事件声明触发时间、事件类型、内容、影响对象与期望触发行为。这两份配置目前由 `ScenarioConfig` 加载为结构化数据,供上层机制使用。

`ScenarioConfig` 是场景加载的统一入口,位于 `framework/config/loader.py`。它会扫描场景目录,把角色、地图、关系、剧情加载为内存对象,并把每个角色的 `role` 字段汇总为 `roles` 字典(供决策导出使用)。

### 3.4 决策与治理平台对接方(离线文件消费者)

这类接入者消费框架导出的决策留痕文件,用于专家评判、训练数据准备或治理展示。文件为 `results/decisions_<模拟名>.json`,由 Simulator 在每步存档时自动生成(需在构造 Simulator 时开启 `export_decisions` 并指定 `decisions_path`)。

文件结构为一个决策事件流,包含模拟名、起始时间、步长、总步数与事件列表。每条事件描述一个 Agent 在某一步的一次决策:角色、职位、动作描述、所在位置、谓词、重要性分、涉他对象、是否伴随对话。事件中的 `category`、`risk_level`、`tags` 三个字段在设计上留给消费方(治理平台)填充分类与风险标注,导出时为空。

## 四、消息契约(protocol.py)

所有实时消息均为 JSON 对象,首字段 `type` 标识消息类型。坐标一律为格子坐标 `[x, y]`(整数),由前端换算世界坐标。传输层可替换,消息结构不变。

### 4.1 agent 消息

单个 Agent 的状态,每个 Agent 思考完成后推送一条。字段包括:角色名 `name`;当前格子坐标 `coord`;寻路路径点数组 `path`(前端沿点平滑移动,不穿墙);当前动作描述 `action`;业务地址 `location`(如"资料室:资料桌");人设当前状态 `currently`;该时间点的对话文本 `conversation`(可选)。

### 4.2 time 消息

模拟时间,整步完成时推送。字段只有一个:时间字符串 `time`,格式为 `"20250213-12:42"`。前端据此更新时钟。

### 4.3 chat_line 消息

对话逐句,每生成一句话立即推送,不等整段对话完成。字段包括说话者 `speaker` 与文本 `text`。前端据此逐句显示对话,获得"实时"观感。

### 4.4 snapshot 消息

全量快照,新连接建立时推送,用于追赶进度。字段包括所有 Agent 的状态字典 `agents`(键为角色名,值为 agent 消息同构的状态)与当前时间 `time`。

### 4.5 done 与 error 消息

`done` 表示模拟正常结束;`error` 表示模拟异常终止,附 `message` 字段说明原因。

### 4.6 消息校验

`framework/runtime/protocol.py` 提供 `validate_message` 函数,对消息做简易合规校验(确认 `type` 合法、`agent` 消息含 `name` 与 `coord`)。服务端广播前会调用该校验;接入方也可用它验证自己收到的消息。

## 五、配置体系

### 5.1 全局默认配置(data/config.json)

`data/config.json` 的 `agent` 节点是 Agent 的全局默认配置,包含:感知配置 `percept`(视野模式、半径、注意力带宽);日程配置 `schedule`(多样性要求与最大尝试次数);思考配置 `think`(LLM 配置、思考间隔、反思重要性阈值 `poignancy_max`);对话迭代数 `chat_iter`;联想记忆配置 `associate`(embedding 提供商、保留条数)。

其中 `think.llm` 决定大模型后端:`provider` 为 `ollama` 或 `openai`(DeepSeek 等兼容 API 可用 `openai`);`model` 为模型名;`base_url` 为服务地址;`concurrency` 为 LLM 并发上限(框架用全局信号量限制同时进行的 LLM 请求数,防止超出后端并发能力造成排队)。

### 5.2 存储选择

记忆存储通过 `associate.embedding.provider` 选择。`simple` 为纯标准库实现(词重叠近似相关性,零第三方依赖,任何环境可跑);`ollama`、`openai`、`hugging_face` 走向量检索(相关性更精确,但依赖对应 embedding 服务)。实时服务默认强制 `simple`,以保证任意环境可启动;需要向量检索时修改配置并确保 embedding 服务可用。

## 六、输出与产物

模拟运行期间,`results/checkpoints/<模拟名>/` 下每步生成一个 `simulate-<时间>.json` 全量存档(包含所有 Agent 的状态、记忆、日程、对话),以及一个 `conversation.json`(全部对话记录)。这些是模拟的原始数据,供续跑与回放。

决策导出 `decisions_<模拟名>.json` 位于 `results/` 根目录,由存档派生,是给治理平台/专家界面的结构化决策留痕。

`results/compressed/` 存放压缩后的回放数据(旧版回放功能遗留,当前入口不再使用)。

## 七、扩展与二次开发

框架的扩展点集中在组件注入:Agent 的 LLM、记忆、空间、提示词、时钟均通过构造参数注入,替换实现不需要改动 Agent 生命周期代码。新增 LLM 提供商只需实现 `LLMProvider` 接口(completion、is_available、get_summary),并在 `framework/runtime/llm.py` 的工厂中注册。新增业务场景只需在 `scenarios/` 下配置目录,框架层零改动。接入新的前端只需实现第四节的消息消费逻辑。

统一日志位于 `framework/runtime/logger.py`,提供 `get_logger(name, level, log_file)` 工厂,框架内所有模块共用;需要文件日志时传入 `log_file` 即可。

## 八、常见问题

模拟启动后页面空白:通常是前端依赖(Phaser)从外网 CDN 加载失败。服务端优先使用 `frontend/static/vendor/phaser.min.js`(本地化),不存在时才回退 CDN。离线环境请将 phaser.min.js 放入该目录。

模拟很慢:瓶颈在 LLM 调用,不在框架。可调整 `think.llm.concurrency`(并发上限)与 `max_workers`(思考线程数),但并发超过 LLM 后端能力不会提速。

需要换模型或接 DeepSeek:修改 `data/config.json` 的 `think.llm`,provider 用 `openai`,base_url 指向兼容端点,`LLM_API_KEY` 通过环境变量提供(密钥不进入版本库)。

对话没有发生:对话由 LLM 自主决定是否发起(带 50% 概率兜底),属于正常行为;多跑几步或检查 `relationships.json` 是否配置了关系。

## 九、版本与回退

框架为自研实现,核心逻辑不依赖第三方多智能体框架。旧版实现(`modules/` 目录及 `start.py`、`live.py`、`compress.py`、`replay.py`)已随框架化移除,可在 git 历史中回退查看。当前唯一入口为 `live_fastapi.py`。
