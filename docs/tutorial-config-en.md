# Tutorial: Configuration Loading & Validation

This tutorial walks you through the mavisframework **configuration system** —
how to prepare role/scenario configs, how to load them, and how to get clear
errors when validation fails. After reading, you'll understand the full
"business-layer config → framework" pipeline.

## Three Layers of Configuration

mavisframework separates configuration into three layers:

| Layer | Content | Maintainer |
|---|---|---|
| **Business layer** (scenarios/) | roles (agent.json), scene (maze.json), relations, story | business team / config tool |
| **Simulation config** | LLM choice, stride, start time, agent list | boot code |
| **agent_base defaults** | perception/schedule/thinking defaults (in `data/config.json`) | developers |

Changing business = changing the scenarios/ directory; the framework itself
stays untouched — this is the core design.

## 1. Role Configuration (agent.json)

A minimal role (fields can be generated by the config tool):

```json
{
  "name": "老周",
  "coord": [10, 6],
  "currently": "正在盯着今天的行情",
  "scratch": {
    "age": 60,
    "innate": "谨慎、情绪化",
    "learned": "多年炒股经验",
    "lifestyle": "早起看盘",
    "daily_plan": "开盘前到资料室看行情"
  },
  "spatial": {
    "address": {"living_area": ["the Ville", "投资咨询中心", "资料室"]},
    "tree": {"the Ville": {"投资咨询中心": {"资料室": ["办公桌"]}}}
  }
}
```

> Note: addresses in `spatial.address.living_area` and `tree` **must include the
> world prefix** (`the Ville`), and leaf addresses must exist in the map (maze.json).

## 2. Loading Simulation Config (load_config)

Use the top-level API `load_config` to create config for a new simulation:

```python
import mavisframework as mf

cfg = mf.load_config(
    start_time="20250213-09:30",   # start simulation time
    stride=2,                       # game minutes per step
    agents=["沈砚之", "老周"],      # participating roles
)
```

The returned `cfg` contains:

```python
cfg["stride"]          # 2
cfg["time"]["start"]   # "20250213-09:30"
cfg["agents"]          # {"沈砚之": {"config_path": "assets/village/agents/沈砚之/agent.json"}, ...}
cfg["agent_base"]      # defaults from data/config.json (perception/schedule/thinking/LLM)
cfg["maze"]["path"]    # "assets/village/maze.json"
```

**Config sources (path injection)**: `load_config` locates two files via
environment variables:

| Env var | Default | Purpose |
|---|---|---|
| `MAVIS_CONFIG_PATH` | `data/config.json` | agent_base defaults (incl. LLM choice) |
| `MAVIS_ASSETS_ROOT` | `assets/village` | static assets (roles/map) relative root |

### Resuming from a Log (load_config_from_log)

Restore a simulation from a previous checkpoint — time advances by one stride:

```python
cfg = mf.load_config_from_log("results/checkpoints/invest-live")
# checkpoint at 09:30, stride=2 → cfg["time"]["start"] == "20250213-09:32"
```

## 3. Validating Config (validate_all)

Config is consumed by the LLM and the map engine — a bad config crashes at
runtime. Use `validate_all` to catch problems early:

```python
import json, glob
import mavisframework as mf

# load all roles
agents = {}
for f in glob.glob("frontend/static/assets/village/agents/*/agent.json"):
    d = json.load(open(f, encoding="utf-8"))
    agents[d["name"]] = d

# load relations & story (may be empty)
rels = json.load(open("scenarios/investment/relationships.json", encoding="utf-8")).get("relations", [])
story = json.load(open("scenarios/investment/story.json", encoding="utf-8")).get("events", [])

# load the map
maze = json.load(open("frontend/static/assets/village/maze.json", encoding="utf-8"))

errors = mf.validate_all(agents, rels, story, maze)
if errors:
    print("Config has problems:")
    for e in errors:
        print("  -", e)
else:
    print("All config valid")
```

**Checks performed**:

| Check | Description |
|---|---|
| Syntax | required fields present; correct types (e.g. `coord` must be `[x, y]`) |
| Map consistency | `coord` within map bounds; `spatial` tree addresses exist in the map |
| Cross-role | relation/story referenced roles exist; story `time` is valid `HH:MM` (00:00-23:59); `importance` in 1-10 |

**Error example** (deliberately broken config):

```python
bad_agent = dict(agents["老周"])
bad_agent["coord"] = [999, 999]   # out of map

errors = mf.validate_agents({"老周": bad_agent}, maze)
print(errors)
# ['[agent:老周].coord [999, 999] 超出地图范围 [30, 20]']
```

## 4. Scenario Config (ScenarioConfig)

`load_scenario` loads all config of a business scenario directory at once:

```python
scenario = mf.load_scenario("scenarios/investment", validate=True)
# with validate=True, config is validated immediately; raises ValueError on failure

scenario.agents          # {name: agent_json}
scenario.maze            # maze.json content
scenario.relationships   # relations list
scenario.story           # events list
```

## Summary

- Config has three layers: business / simulation / agent_base defaults
- `load_config` for a new simulation, `load_config_from_log` to resume
- `validate_all` / `validate_agents` / `validate_relationships` / `validate_story` for layered validation
- Addresses must carry the world prefix; story `time` must be valid `HH:MM`
